未尽之言

  1. 识别文件：文件头是 II*\0，所以它实际是 TIFF，并非 zip
  2. 元数据：XMP 标签和 XPComment 标签给出「蓝色月面、最浅一层、六十四格、照镜子」
  3. B 通道 LSB：在蓝色通道的最低位中取出 KEY 和 IV
  4. 解密：把开头带 = 的 base64 字符串反转，结果解出 32 字节密文；再用 ROT13 和反转处理一次，然后用 AES-256-CBC 解密，得到 7z 密码 InkBeneath_Moon_2026
  5. 尾部附着的 7z：从偏移 0x1d284 开始截取，得到 PDF
  6. PDF 隐写：PDF 每一段末尾多出一个 ASCII 字符，凑成 32 个字符后再做 base64 解码

然后我盯着 syscall 想了想：这指令进内核的时候，会把下一条指令的地址塞进 rcx（顺便把 rflags 塞进 r11），返回之后也不还原
而第一次 syscall 的时候 rax=0 / rdi=0 / rsi=0 / rdx=0，也就是 read(0, NULL, 0) —— count == 0 时内核直接返回 0，根本不会去碰那个 NULL 指针，于是：

  • rax 还是 0，下一次 syscall 依然是 read
  • rcx = 0x400002，一个指向我们自己那页 RWX 内存的合法地址
